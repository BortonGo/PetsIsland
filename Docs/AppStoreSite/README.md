# Сайт Pet Island

Готовый статический сайт на русском и английском: знакомство с приложением, поддержка и политика конфиденциальности. Работает без JavaScript, сборщика, cookies, внешних шрифтов и аналитики. Скриншоты показывают текущий интерфейс приложения; рисунки питомцев не менялись.

**Статус:** подготовлен локально, в интернете ещё не опубликован. Кнопки загрузки нет, пока приложение не выпущено. В App Store Connect нужны публичные HTTPS-адреса, а не путь к файлу или localhost.

## Проверить локально

Из корня проекта:

```sh
python3 -m http.server 8765 --bind 127.0.0.1 --directory Docs/AppStoreSite
```

Открой `http://127.0.0.1:8765/`. Остановить сервер — `Ctrl+C`. Поддержка открывается по якорю `#support`, FAQ раскрываются без скриптов; переключатель языка ведёт на соответствующую страницу, включая политику.

## Опубликовать через GitHub Pages

Для сайта достаточно отдельного публичного репозитория. Публиковать исходники iOS-приложения не требуется.

1. Создай репозиторий `pet-island-support` в своём GitHub-аккаунте. На GitHub Free для Pages нужен публичный репозиторий.
2. Скопируй в **корень нового репозитория** только `index.html`, `privacy.html`, `style.css`, каталоги `assets/` и `en/`, а также пустой файл `.nojekyll` из этой папки. Не загружай весь проект, `outputs/`, App Store metadata или этот README как страницы сайта.
3. Сохрани файлы в ветке `main`. В Settings → Pages выбери **Deploy from a branch → main → / (root)** и сохрани.
4. Дождись успешной публикации. Возьми настоящий адрес из **Settings → Pages → Visit site**. Проверь HTTPS и включи Enforce HTTPS, если доступно.
5. Открой русскую и английскую главные страницы и обе политики в приватном окне, без входа в GitHub. Проверь картинки, язык, FAQ и email на iPhone.

Источник: [создание GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site). Можно использовать другой статический HTTPS-хостинг: сайт не привязан к GitHub и не требует серверного приложения.

В будущем для обновления сайта копируй те же файлы в тот же репозиторий. Держи прежние URL поддержки и политики рабочими.

## Какие адреса куда вставить

Допустим, **BASE** — фактический HTTPS-адрес корня опубликованного сайта с завершающим `/`. Это обозначение, не текст для вставки в App Store Connect.

| Поле | Русский | English (U.S.) |
| --- | --- | --- |
| Support URL | BASE + `index.html#support` | BASE + `en/index.html#support` |
| Marketing URL (необязательно) | BASE + `index.html` | BASE + `en/index.html` |
| Privacy Policy URL | BASE + `privacy.html` | BASE + `en/privacy.html` |

После публикации добавь **настоящую ссылку политики внутрь приложения** рядом с доступным офлайн-текстом. Сейчас в `SupportPrivacyView` есть офлайн-политика и email, а URL ещё нет. Это отдельный небольшой шаг после появления домена. Apple требует ссылку и в App Store Connect, и внутри приложения: [правило 5.1.1](https://developer.apple.com/app-store/review/guidelines/#data-collection-and-storage).

## Изображения и обновление

`assets/app-icon.png` — уменьшенная копия основной иконки из каталога приложения. `assets/{ru,en}-*.png` — уменьшенные до 660 px по ширине копии финальных снимков из `../AppStore/Screenshots/`. На сайт не подключаются файлы из исходников приложения: папка автономна.

Для магазина используй исходные PNG полного разрешения из [пакета App Store](../AppStore/README.md), а не уменьшенные изображения сайта. Временные сборки, генераторы HTML, контакты для ревью и служебные снимки не входят в публикуемую папку.
